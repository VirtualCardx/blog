## 一、这个仓库是什么

[jailbreaks](https://github.com/togg53192-cmd/jailbreaks/) 是 GitHub 用户 togg53192-cmd 维护的一个公开仓库，副标题直白地写着「LIST OF ALL MY JAILBREAKS」。它收录了 **31 条提示词，覆盖 25+ 个模型**，文件形态包括完整的系统提示词（system prompt）、人格锁定（persona lock）、工作区策略（workspace policy）、`AGENTS.md` 文件、配置块和 Ollama Modelfile。

仓库的自我定位是「研究教育用途」：文档里说明它记录的是**指令层级（instruction hierarchy）、人格框架（persona framing）、提示冲突（prompt conflicts）与策略覆盖（policy overrides）**如何影响模型行为——这也正是提示词安全研究的核心议题。

## 二、它覆盖了哪些模型

仓库按厂商分组，覆盖面相当广，这是它受关注的主要原因：

| 分组 | 收录内容 |
| ---- | -------- |
| OpenCode Zen 免费隐身模型 | Big Pickle、Space Bunny、LongCat、MiMo、Step 5、Muse Spark 等 8 条 |
| Anthropic | Claude Opus / Sonnet 各两个版本 |
| 智谱 | GLM-5.2 / 5.3 全系，含 ZCode 版本与配套 AGENTS.md |
| DeepSeek | V3、V4、4.1 |
| 月之暗面 | Kimi K2、K3 |
| xAI | Grok Build、Grok 4.7 及配置文件 |
| Google / Mistral / 阿里 | Gemini 4、Mistral Large 4、Qwen 3.7 |
| Ollama 本地模型 | Gemma 4、GPT-OSS 20B 的 Modelfile |

值得一提的两个特点：

1. **文件是全量可粘贴的**——不是摘要或片段，每条都是完整提示词，仓库明确拒绝「缩水版」投稿
2. **版本化管理**——同一模型的迭代会用 v1/v2 显式区分，而不是悄悄覆盖，方便对比行为变化

## 三、为什么这类仓库有研究价值

抛开猎奇视角，这类合集对三类人有实际意义：

- **提示词安全研究者**：它是观察「模型在什么指令结构下会偏离既定策略」的现成语料库，可以直接用作红队测试的输入集
- **应用开发者**：如果你在构建带 AI Agent 的产品，了解这类攻击面的形态，才能设计更稳的指令优先级和输入过滤——仓库 README 也明确写了「帮助开发者加固系统以抵抗提示注入」
- **模型选型人员**：它可以粗略当作一个「各模型指令遵循强度」的参照样本，哪些模型容易被覆盖、哪些扛得住，都有社区反馈可循

## 四、时效性与维护方式

提示词类仓库最大的问题是**快速过期**。模型每次更新，指令层级可能变化，系统提示词会轮换，昨天有效的文件今天可能失效。这个仓库的处理方式是靠社区维护：发现文件失效就开 issue，欢迎提交更新版本，贡献规范里明确要求「一文件一提示词、全量内容、注明用途位置、版本变更显式标注」。

## 五、必须说清楚的风险与边界

介绍归介绍，几条底线要明确：

1. **仅供研究教育**。这类材料的正当用途是安全研究和防御加固，用它去实际越狱生产环境的模型，大概率违反模型厂商的服务条款，部分司法辖区还可能触碰法律红线
2. **对内容本身保持警惕**。越狱提示词社区鱼龙混杂，下载的文件可能夹带其他东西，引用前自己审一遍
3. **不要用于伤害他人或违法用途**——这是仓库自己的免责声明，也是任何使用的前提
4. 国内用户额外注意：相关研究应在合规框架内进行，公开传播越狱内容在国内平台同样有合规风险

## 六、小结

jailbreaks 仓库本质上是一份持续维护的「LLM 指令遵循弱点样本库」：覆盖广（25+ 模型）、文件全（可直接使用）、版本清晰。对做 AI 安全、Agent 产品开发的人来说是有价值的参照物；对普通用户来说，了解它存在、知道这类攻击面的形态，比实际去用它更重要。
